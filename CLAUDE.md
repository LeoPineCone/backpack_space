# Working on this repo

- Repo language is English: code, comments, data, docs, CLI output.
- `packages/core/src/` must stay free of Node APIs (no fs, no process) – the core runs in the client and on the server. Its own tsconfig has no Node/DOM types, so `npm run typecheck` catches violations. Node-only helpers go to `packages/core/node/`.
- A future client only replays what the core computes; it never decides battle outcomes.
- The core is deterministic: no Math.random, no clock reads. Randomness only via `Rng` with a seed.
- Raise `ENGINE_VERSION` in `packages/core/src/simversion.ts` when a core logic change can change a fight, a shop or a run. Data changes change the simulation version by themselves.
- Game values belong in `data/*.json`, not in code. Item rules text is generated from the effect data (`describe.ts`), never written by hand.
- Items are maintained directly in `data/items/*.json` (no generator scripts). Before adding or changing an item, follow `.claude/skills/item-design/SKILL.md` (size by type, price, number budget, checks). Every item and bag needs a picture brief in `data/item-art.json` (ends with "Accent: <palette colour>."); write and rewrite those with `.claude/skills/item-art/SKILL.md` (inventive, clearly space-themed, one animal per pet). A new effect idea that the effect schema cannot express needs a schema + battle change first.
- UI colours, fonts and button kinds come from `data/theme.json` (`docs/theme.md`); never write a colour into client code.
- Screens, navigation and player actions follow `docs/ux.md`; a new screen or action goes there first.
- Menu backgrounds (turning planets): follow `.claude/skills/planet-art/SKILL.md`.
- Hero pictures (look drafts, model sheet, full body, head, home scene, later skins): follow `.claude/skills/hero-art/SKILL.md`.
- Places of the world (planets, moons, stations, stars) and which items and heroes come from them live in `lore/planets.json`; after changes run `npm run lore` (rewrites `lore/graph.html`).
- Game words come from `data/glossary.json` (English for game and code, German for design talk); add a term there before using a new word in the game.
- Every text the player sees goes through the language files (`data/locales/*.json`, see `docs/i18n.md`); the client never shows a hard-coded word. English is the source; new items and texts also need their German translation (`npm run i18n` lists what is missing).
- After changes: `npm run check` (validate, typecheck, lint, test; the same as the pull request check). After item changes also `npm run catalog`.
- Balancing (numbers, new heroes or items, hero rules, measuring): follow `.claude/skills/balancing/SKILL.md` (procedure, targets, how exact the tools are, lessons learned).
- No alcohol in the game.
- Not a clone: no names, characters or look of Backpack Brawl or other existing games.
- Tech stack is decided: TypeScript, PixiJS, Capacitor (same as backpack_race). The client lives in `apps/client` (PixiJS, placeholder symbols instead of art); it only shows and replays what the core computes and never decides a rule or a fight. `playground/` is a design tool, not product code.
- Phone safe area: outside it (status bar, notch, camera island, home indicator) the client draws only backgrounds. Lay screens out between y = 0 and `H` (`apps/client/src/screen.ts`, `docs/mobile.md`).
