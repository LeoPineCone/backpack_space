# Languages

The game ships in several languages from one build. Currently: English (source language) and German.

## How it works

- **One build, all languages.** Every language file is bundled into the client, so the same app goes to every store and every country. No separate builds per language.
- **Start language = device language.** On the first start the client takes the phone's (or browser's) language list and picks the first language the game has. If none matches, the game is in English.
- **Switchable in the settings.** The settings screen (slider button on the hero screen) offers "Device language" and every shipped language. The choice is stored on the device.
- **English is the fallback.** A text that is missing in a language shows in English instead of breaking, so a new item can ship before its translation.

## Where texts live

| What | English (source) | Other languages |
|---|---|---|
| Buttons, messages, screen titles (`ui.*`, `toast.*`) | `data/locales/en.json` | `data/locales/<lang>.json` |
| Rules text sentence parts (`rules.*`, `noun.*`, `list.*`) | `data/locales/en.json` | `data/locales/<lang>.json` |
| Item names (`item.<id>`) | `name` in `data/items/*.json` | `data/locales/<lang>.json` |
| Hero name, title, focus (`hero.<id>.name/title/focus`) | `data/heroes.json` | `data/locales/<lang>.json` |
| Glossary words (`term.<id>`) | `en` in `data/glossary.json` | German: `de` in `data/glossary.json`; others: `data/locales/<lang>.json` |
| Glossary meanings (`term.<id>.text`), group titles (`group.<id>`) | `data/glossary.json` | `data/locales/<lang>.json` |

The client never shows a hard-coded word: it asks for a key (`t("ui.start")`), and a test fails if a screen text bypasses the language files.

The item rules text stays generated from the effect data (`packages/core/src/describe.ts`); only its sentence parts are translated. For example `rules.when.shipUse` is "When one of your {tag|other} activates" in English and "Wenn {tag|indef} in deinem Rucksack auslöst" in German. `{tag|form}` writes a type word in the grammatical form a language needs (`noun.weapon.indef` = "eine Waffe"), so German can decline its words without changing code. Numbers use the language's decimal mark (`number.decimal`: "2.5 s" / "2,5 s").

## Checks

- `npm run validate` prints per language whether it is complete.
- `npm run i18n` lists every missing text (with the English original) and every left-over key, ready to hand to a translator.
- Broken translations stop `validate`: placeholders that differ from English, or a word form a sentence needs but the language lacks.
- `npm test` renders every item, hero and glossary text in every language and looks for leftover keys or placeholders.

## Adding a language

1. Copy `data/locales/de.json` to `data/locales/<code>.json` (two-letter ISO code, e.g. `fr`), set `language.name` to the language's own name ("Français") and translate every value. Keep the keys and the `{placeholders}`; the `noun.*` forms may differ per language (add the forms your sentences use).
2. Add the glossary words as `term.<id>` entries in that file (English and German keep theirs in `data/glossary.json`).
3. `npm run i18n` until it says complete, then `npm run validate && npm run typecheck && npm test`.

Nothing else changes: the language appears in the settings and is picked automatically on devices set to it. The store listing (app name, description, screenshots) is translated separately in the store consoles; Capacitor needs no change for in-game languages.
